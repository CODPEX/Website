# Commands & Setup

## Main commands

```bash
python3 rkp_toolkit.py all      # self-check + issue + package (default)
python3 rkp_toolkit.py check    # self-check only
python3 rkp_toolkit.py probe    # print HAL version and supported curves
python3 rkp_toolkit.py issue    # fetch EEK, build CSR, submit to Google
python3 rkp_toolkit.py keybox   # package keybox.xml from existing certificates
python3 rkp_toolkit.py verify   # verify an existing keybox.xml
```

`all` is what `issue.sh` runs by default.

## Flags

| Flag | Meaning |
|---|---|
| `--workdir DIR` | Working directory (default `rkp_out`) |
| `-o FILE` | Output keybox path |
| `--no-archive` | Keep artifacts in place, skip archiving |

Example:

```bash
python3 rkp_toolkit.py all --workdir ~/rkp_work -o ~/rkp_work/my-keybox.xml
```

## Mirror setup

`setup.sh` handles everything automatically: **benchmark mirrors → write `sources.list` → install dependencies → self-check**. Normally you never call it directly; `issue.sh` invokes it when something is missing.

### Manual usage

```bash
sh setup.sh              # benchmark and pick the fastest mirror
sh setup.sh --cn         # China mirrors only
sh setup.sh --global     # global mirrors only
sh setup.sh --mirror URL # force a specific mirror
sh setup.sh --restore    # restore the saved configuration
sh setup.sh --repair     # clear apt locks and stale indexes
sh setup.sh --dry-run    # benchmark only, change nothing
```

### How mirror selection works

For each candidate mirror, the script measures the round-trip latency of `$base/termux-main/dists/stable/Release` and picks the fastest. Latency is measured from the device, so results differ between networks.

The written configuration looks like:

```bash
# /data/data/com.termux/files/usr/etc/apt/sources.list
deb https://mirrors.bfsu.edu.cn/termux/apt/termux-main/ stable main
```

The previous configuration is backed up as `sources.list.rkp.bak`, and `--restore` brings it back.

### Automatic fallback

After writing the mirror, `setup.sh` runs `pkg update`. On failure it automatically retries with the next fastest mirror until one works. If every mirror fails:

- dependencies already present → restore the original configuration and continue
- dependencies missing → restore the original configuration and exit with guidance

A backup is only created when the existing configuration was not generated by this tool.

### Local problems are detected

When all mirrors fail, the script prints the real apt error (last 12 lines) and checks for local issues:

| Detected | Meaning | Action |
|---|---|---|
| `lock` | apt lock exists | Stop switching, suggest `--repair` |
| `dns` | DNS resolution failed | Check network |
| `keyring` | GPG signature failure | Suggest `termux-change-repo` |
| `disk` | Out of space | Clean up |

Local problems cannot be fixed by changing mirrors, so the script stops immediately instead of trying all eight candidates.

## Dependencies

| Package | Purpose |
|---|---|
| `python` | Runs the toolkit |
| `python-cryptography` | Certificate parsing and packaging |
| `curl` | Talks to the Google RKP server |

`rkp_bridge.jar` is bundled; apart from the system `app_process`, no extra Java runtime is required on the device.

> Do not `pip install cryptography` on Termux: it compiles from source and fails to link `libssl`. Use `pkg install python-cryptography` instead. `setup.sh` already handles this.

## Self-test

`rkp_csr.py` verifies the Android 13 CSR assembly logic without a device:

```bash
python3 rkp_csr.py
```

It runs eight assertion groups covering byte layout, truncation detection, and CBOR encoding, then prints `ALL TESTS PASSED`.
