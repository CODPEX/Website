# 概览

RKP Toolkit 是由 [@kanseijo](https://github.com/kanseijo) 维护的外部开源项目。它通过设备自身的 RKP HAL 向 Google 申请远程密钥配置（RKP）证书，并打包为 TEESimulator 可用的 `keybox.xml`。

> **外部作品。** 本项目不由 CODPEX 维护，环境要求、行为与支持均以上游仓库为准。请始终参考[原始 README](https://github.com/kanseijo/rkp-toolkit) 获取最新信息。

## 它做什么

- 通过内置桥接程序（`rkp_bridge.jar`）调用设备的 `IRemotelyProvisionedComponent` HAL
- 从 `remoteprovisioning.googleapis.com` 获取端到端加密密钥链（EEK）
- 由设备 TEE 生成并签名 CSR，再提交给 Google
- 将返回的证书链与 SEC1 私钥打包为 `keybox.xml`

工具只负责生成文件，**绝不自动部署**。

## 环境要求

| 要求 | 说明 |
|---|---|
| Android 12 或更高 | 需要 RKP HAL（`IRemotelyProvisionedComponent`） |
| 已 root | 访问 RKP HAL 必须 root |
| Termux v0.118.3+ | **不要**从 Google Play 安装 Termux |
| 可访问 Google | 需能访问 `remoteprovisioning.googleapis.com` |

## 实测设备

以下结果来自上游项目，仅供参考，不构成承诺：

| 设备 | 系统 | 结果 |
|---|---|---|
| OnePlus Ace 6 (PLQ110) | Android 16 | 可用 |
| ASUS ROG Phone 9 Pro | Android 15 | 可用 |
| Redmi Note 11 (spes) | Android 13 | 无 RKP HAL |
| OnePlus Ace 3 (PJE110) | A15 系统 + A13 厂商分区 | HAL 缺少 v3 方法 |

后两者的失败并非工具缺陷：只要有一台未修改的设备成功，说明工具链本身是正常的。

## 仓库结构

```text
.
├── issue.sh              # 入口
├── setup.sh              # 镜像测速 + 依赖
├── rkp_toolkit.py        # 主逻辑
├── rkp_csr.py            # Android 13 CSR 组装
├── build.sh              # 重建 jar
├── rkp_bridge.jar        # HAL 桥接（已内置）
├── src/
│   ├── RkpBridge.java    # 反射调用 RKP HAL
│   └── RkpProbe.java     # HAL 探测
├── docs/
│   └── android13-rkp-research.md
├── README.md
├── README.zh-CN.md
├── SECURITY.md
├── CONTRIBUTING.md
└── LICENSE
```

`rkp_bridge.jar` 已提交入库，Termux 用户无需自行构建。
